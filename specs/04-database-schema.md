|---|---|

This document is the single source of truth for table names, column names and allowed values. Every other document uses these names exactly. If a name must change, change it here first.

## 1. Conventions

| Topic | Rule |
|---|---|
| Naming | `snake_case`. Table names are plural. Foreign keys end in `_id` (uuid or integer key) or `_code` (text key). |
| Primary keys | `id uuid`, a UUIDv7 generated in Rust with `Uuid::now_v7()`. The column also has `DEFAULT uuidv7()` so seeds and tests can omit it. |
| Lookup keys | Small lookup tables (religions, sects, castes, languages and so on) use a stable `code text` primary key such as `islam` or `rajput_bhatti`. Codes are lowercase ASCII, digits and underscores. They appear in API payloads, so they never change once released. |
| Large lookups | `regions` and `cities` use `integer` identity keys because the data set is large. |
| Enumerations | Stored as `text` with a `CHECK` constraint, not as PostgreSQL `ENUM` types. Reason: `sqlx` maps `text` to `String` with no type annotations, arrays are plain `text[]`, and adding a value is a one-line constraint change. In Rust, each enumeration is an `enum` with `#[derive(sqlx::Type)]`, `#[sqlx(type_name = "text", rename_all = "snake_case")]` and matching `serde` renames. |
| Timestamps | `timestamptz`, always UTC. Every mutable table has `created_at` and `updated_at`. `updated_at` is maintained by the `set_updated_at()` trigger. |
| Booleans | Named as a statement: `is_primary`, `has_approved_photo`, `show_last_active`. |
| Phone numbers | E.164 text, for example `+923001234567`. |
| Free text | Always has a length `CHECK`. The API trims and normalises whitespace before saving. |
| Deletion | Users and profiles are never hard-deleted. They are scrubbed and kept as tombstones (section 12). Child rows that only make sense with their parent use `ON DELETE CASCADE`. |
| Pairs | Symmetric pairs (connections) store the two profile ids ordered, `profile_low_id < profile_high_id`, so one pair has one row. |
| Migrations | `apps/api/migrations/NNNN_name.sql`, applied by `sqlx::migrate!` at startup. Never edit a migration after it has been merged; add a new one. |

## 2. Helpers

```sql
-- 0001_extensions_and_helpers.sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;

CREATE FUNCTION set_updated_at() RETURNS trigger
LANGUAGE plpgsql AS $$
BEGIN
    NEW.updated_at := now();
    RETURN NEW;
END;
$$;
```

For every table that has an `updated_at` column, add this trigger (replace `<table>`):

```sql
CREATE TRIGGER <table>_set_updated_at
    BEFORE UPDATE ON <table>
    FOR EACH ROW EXECUTE FUNCTION set_updated_at();
```

On Azure, `pg_trgm` must be allow-listed in the `azure.extensions` server parameter before the migration runs.

## 3. Reference tables

All reference rows except `regions` and `cities` are loaded into the API's memory at startup (they are small) and served by `GET /v1/reference/bootstrap`. Regions and cities are queried on demand.

```sql
-- 0002_reference_tables.sql

CREATE TABLE countries (
    code        text PRIMARY KEY CHECK (code ~ '^[A-Z]{2}$'),   -- ISO 3166-1 alpha-2
    name        text NOT NULL,
    name_ur     text,
    dial_code   text,                                           -- '+92'
    sort_order  integer NOT NULL DEFAULT 1000,                  -- Pakistan first, then common diaspora countries
    is_active   boolean NOT NULL DEFAULT true
);

CREATE TABLE regions (                                          -- province, state or territory
    id            integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    country_code  text NOT NULL REFERENCES countries (code),
    name          text NOT NULL,
    name_ur       text,
    UNIQUE (country_code, name)
);

CREATE TABLE cities (
    id            integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    country_code  text NOT NULL REFERENCES countries (code),
    region_id     integer REFERENCES regions (id),
    name          text NOT NULL,
    name_ur       text,
    latitude      double precision,
    longitude     double precision,
    population    integer,
    is_major      boolean NOT NULL DEFAULT false                -- shown first in pickers
);
CREATE INDEX cities_country_region_idx ON cities (country_code, region_id);
CREATE INDEX cities_name_trgm_idx ON cities USING gin (name gin_trgm_ops);

CREATE TABLE religions (
    code        text PRIMARY KEY,
    name        text NOT NULL,
    name_ur     text,
    sort_order  integer NOT NULL DEFAULT 100,
    is_active   boolean NOT NULL DEFAULT true
);

CREATE TABLE sects (
    code           text PRIMARY KEY,
    religion_code  text NOT NULL REFERENCES religions (code),
    name           text NOT NULL,
    name_ur        text,
    sort_order     integer NOT NULL DEFAULT 100,
    is_active      boolean NOT NULL DEFAULT true
);
CREATE INDEX sects_religion_idx ON sects (religion_code);

-- Two levels only: a caste (parent_code IS NULL) and its sub-castes (parent_code = caste code).
CREATE TABLE castes (
    code         text PRIMARY KEY,
    parent_code  text REFERENCES castes (code),
    name         text NOT NULL,
    name_ur      text,
    aliases      text[] NOT NULL DEFAULT '{}',                  -- alternative spellings, used by search
    sort_order   integer NOT NULL DEFAULT 100,
    is_active    boolean NOT NULL DEFAULT true
);
CREATE INDEX castes_parent_idx ON castes (parent_code);
CREATE INDEX castes_name_trgm_idx ON castes USING gin (name gin_trgm_ops);

-- "Other" values typed by users. Moderators promote popular ones into `castes`.
CREATE TABLE caste_suggestions (
    id               uuid PRIMARY KEY DEFAULT uuidv7(),
    parent_code      text REFERENCES castes (code),             -- NULL: suggested as a top-level caste
    name             text NOT NULL CHECK (char_length(name) BETWEEN 2 AND 60),
    normalized_name  text NOT NULL,                             -- lowercase, single spaces
    usage_count      integer NOT NULL DEFAULT 1,
    status           text NOT NULL DEFAULT 'pending' CHECK (status IN ('pending', 'promoted', 'rejected')),
    promoted_code    text REFERENCES castes (code),
    created_at       timestamptz NOT NULL DEFAULT now(),
    updated_at       timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX caste_suggestions_unique_idx
    ON caste_suggestions (COALESCE(parent_code, ''), normalized_name);

CREATE TABLE languages (
    code        text PRIMARY KEY,
    name        text NOT NULL,
    name_ur     text,
    sort_order  integer NOT NULL DEFAULT 100,
    is_active   boolean NOT NULL DEFAULT true
);

CREATE TABLE education_levels (
    code        text PRIMARY KEY,
    name        text NOT NULL,
    name_ur     text,
    rank        smallint NOT NULL,                              -- higher is more education, used for "at least" preferences
    sort_order  integer NOT NULL DEFAULT 100,
    is_active   boolean NOT NULL DEFAULT true
);

CREATE TABLE education_fields (
    code        text PRIMARY KEY,
    name        text NOT NULL,
    name_ur     text,
    sort_order  integer NOT NULL DEFAULT 100,
    is_active   boolean NOT NULL DEFAULT true
);

CREATE TABLE profession_categories (
    code        text PRIMARY KEY,
    name        text NOT NULL,
    name_ur     text,
    sort_order  integer NOT NULL DEFAULT 100,
    is_active   boolean NOT NULL DEFAULT true
);

-- Monthly income bands. `rank` is comparable across currencies (same rank is roughly the same purchasing level).
CREATE TABLE income_bands (
    code           text PRIMARY KEY,
    currency_code  text NOT NULL CHECK (currency_code ~ '^[A-Z]{3}$'),
    label          text NOT NULL,
    label_ur       text,
    min_amount     bigint NOT NULL,
    max_amount     bigint,                                      -- NULL: no upper limit
    rank           smallint NOT NULL,
    sort_order     integer NOT NULL DEFAULT 100,
    is_active      boolean NOT NULL DEFAULT true
);

CREATE TABLE hobbies (
    code        text PRIMARY KEY,
    name        text NOT NULL,
    name_ur     text,
    category    text NOT NULL,
    sort_order  integer NOT NULL DEFAULT 100,
    is_active   boolean NOT NULL DEFAULT true
);
```

Rules:

- Reference rows are never deleted. Set `is_active = false` to retire one. Retired rows stay valid on existing profiles but disappear from pickers.
- The two-level limit on `castes` is enforced by the API (a row whose parent has a parent is rejected), not by the database.

## 4. Users and accounts

A `users` row mirrors one Clerk user. It holds identity and account state only. Everything about the marriage candidate lives in `profiles`.

```sql
-- 0003_users.sql

CREATE TABLE users (
    id                     uuid PRIMARY KEY DEFAULT uuidv7(),
    clerk_user_id          text NOT NULL UNIQUE,                -- Clerk "user_..." id, the JWT `sub`
    email                  text,
    email_verified         boolean NOT NULL DEFAULT false,
    phone_e164             text,
    phone_verified         boolean NOT NULL DEFAULT false,
    role                   text NOT NULL DEFAULT 'member'
                           CHECK (role IN ('member', 'moderator', 'admin')),
    status                 text NOT NULL DEFAULT 'active'
                           CHECK (status IN ('active', 'suspended', 'banned', 'deletion_scheduled', 'deleted')),
    status_reason          text,                                -- shown to the user on the blocked screen
    suspended_until        timestamptz,                         -- only for status = 'suspended'
    locale                 text NOT NULL DEFAULT 'en' CHECK (locale IN ('en', 'ur')),
    timezone               text NOT NULL DEFAULT 'Asia/Karachi',
    last_seen_at           timestamptz,
    deletion_requested_at  timestamptz,
    purge_after            timestamptz,                         -- deletion_requested_at + 30 days; may also be set on a banned user (06 section 9)
    deleted_at             timestamptz,
    created_at             timestamptz NOT NULL DEFAULT now(),
    updated_at             timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX users_email_idx ON users (lower(email));
CREATE INDEX users_phone_idx ON users (phone_e164);
CREATE INDEX users_purge_idx ON users (purge_after) WHERE purge_after IS NOT NULL;

-- One row per acceptance of a legal document version.
CREATE TABLE user_consents (
    id           uuid PRIMARY KEY DEFAULT uuidv7(),
    user_id      uuid NOT NULL REFERENCES users (id) ON DELETE CASCADE,
    document     text NOT NULL CHECK (document IN (
                     'terms', 'privacy', 'community_guidelines', 'age_declaration', 'candidate_consent')),
    version      text NOT NULL,                                 -- for example '2026-11-01'
    accepted_at  timestamptz NOT NULL DEFAULT now(),
    ip_address   inet,
    user_agent   text,
    UNIQUE (user_id, document, version)
);

-- Push notification targets.
CREATE TABLE user_devices (
    id            uuid PRIMARY KEY DEFAULT uuidv7(),
    user_id       uuid NOT NULL REFERENCES users (id) ON DELETE CASCADE,
    platform      text NOT NULL CHECK (platform IN ('android', 'web')),
    push_token    text NOT NULL UNIQUE,                         -- FCM registration token
    app_version   text,
    device_model  text,
    last_seen_at  timestamptz NOT NULL DEFAULT now(),
    created_at    timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX user_devices_user_idx ON user_devices (user_id);
```

## 5. Profiles

One user manages exactly one profile at launch (`profiles.user_id` is unique). All interaction tables reference `profiles.id`, never `users.id`, so that lifting this limit later (a parent managing two children) needs no change to those tables.

### 5.1 profiles

All columns except the bookkeeping ones are nullable because the row is created empty at sign-up and filled step by step during onboarding. The constraint `profiles_required_when_submitted` guarantees that a profile cannot leave `draft` with required fields missing.

```sql
-- 0004_profiles.sql

CREATE TABLE profiles (
    id                       uuid PRIMARY KEY DEFAULT uuidv7(),
    user_id                  uuid NOT NULL UNIQUE REFERENCES users (id),
    public_code              text NOT NULL UNIQUE CHECK (public_code ~ '^KR[0-9A-HJKMNP-TV-Z]{8}$'),

    -- lifecycle
    status                   text NOT NULL DEFAULT 'draft' CHECK (status IN (
                                 'draft', 'pending_review', 'changes_requested', 'active',
                                 'paused', 'closed', 'suspended', 'deleted')),
    status_reason            text,                              -- moderator note shown to the owner
    onboarding_step          text NOT NULL DEFAULT 'account_for' CHECK (onboarding_step IN (
                                 'account_for', 'basics', 'community', 'location', 'education_career',
                                 'family', 'lifestyle', 'photos', 'preferences', 'identity', 'review', 'done')),
    onboarding_completed_at  timestamptz,
    first_activated_at       timestamptz,                       -- first time status became 'active'
    paused_at                timestamptz,
    closed_at                timestamptz,
    closed_reason            text CHECK (closed_reason IN (
                                 'found_match_here', 'found_match_elsewhere', 'taking_a_break', 'other')),

    -- who manages the profile
    managed_by               text CHECK (managed_by IN ('self', 'parent', 'sibling', 'relative', 'friend')),
    manager_name             text CHECK (char_length(manager_name) <= 80),

    -- basics
    first_name               text CHECK (char_length(first_name) BETWEEN 2 AND 40),
    last_name                text CHECK (char_length(last_name) BETWEEN 2 AND 40),
    gender                   text CHECK (gender IN ('male', 'female')),
    date_of_birth            date CHECK (date_of_birth > DATE '1930-01-01'),
    marital_status           text CHECK (marital_status IN (
                                 'never_married', 'divorced', 'widowed', 'separated',
                                 'nikah_ended_before_rukhsati', 'married')),
    children_status          text CHECK (children_status IN ('none', 'living_with_me', 'not_living_with_me')),
    children_count           smallint CHECK (children_count BETWEEN 0 AND 15),
    current_wives_count      smallint CHECK (current_wives_count BETWEEN 1 AND 3),   -- only when marital_status = 'married'

    -- appearance and health
    height_cm                smallint CHECK (height_cm BETWEEN 122 AND 213),
    weight_kg                smallint CHECK (weight_kg BETWEEN 30 AND 200),
    complexion               text CHECK (complexion IN ('very_fair', 'fair', 'wheatish', 'brown', 'dark')),
    body_type                text CHECK (body_type IN ('slim', 'average', 'athletic', 'heavy')),
    blood_group              text CHECK (blood_group IN (
                                 'a_pos', 'a_neg', 'b_pos', 'b_neg', 'ab_pos', 'ab_neg', 'o_pos', 'o_neg')),
    disability               text CHECK (disability IN (
                                 'none', 'physical', 'visual', 'hearing', 'speech', 'chronic_illness', 'other')),
    disability_details       text CHECK (char_length(disability_details) <= 300),

    -- religion and community
    religion_code            text REFERENCES religions (code),
    sect_code                text REFERENCES sects (code),
    caste_code               text REFERENCES castes (code),
    sub_caste_code           text REFERENCES castes (code),
    caste_other              text CHECK (char_length(caste_other) BETWEEN 2 AND 60),
    sub_caste_other          text CHECK (char_length(sub_caste_other) BETWEEN 2 AND 60),
    mother_tongue_code       text REFERENCES languages (code),

    -- location
    nationality_code         text REFERENCES countries (code),
    country_code             text REFERENCES countries (code),
    region_id                integer REFERENCES regions (id),
    city_id                  integer REFERENCES cities (id),
    city_other               text CHECK (char_length(city_other) BETWEEN 2 AND 60),
    area                     text CHECK (char_length(area) <= 80),             -- neighbourhood or town
    residency_status         text CHECK (residency_status IN (
                                 'citizen', 'permanent_resident', 'work_visa', 'student_visa',
                                 'dependent_visa', 'visit_visa', 'other')),
    origin_city_id           integer REFERENCES cities (id),                   -- family's home town in Pakistan
    origin_other             text CHECK (char_length(origin_other) <= 60),
    relocation               text CHECK (relocation IN ('not_willing', 'within_country', 'abroad', 'anywhere')),

    -- education and career
    education_level_code     text REFERENCES education_levels (code),
    education_field_code     text REFERENCES education_fields (code),
    degree_title             text CHECK (char_length(degree_title) <= 80),
    institute_name           text CHECK (char_length(institute_name) <= 120),
    employment_type          text CHECK (employment_type IN (
                                 'private_job', 'government_job', 'armed_forces', 'business_owner',
                                 'self_employed', 'student', 'homemaker', 'not_working', 'retired')),
    profession_code          text REFERENCES profession_categories (code),
    job_title                text CHECK (char_length(job_title) <= 80),
    employer_name            text CHECK (char_length(employer_name) <= 120),
    income_band_code         text REFERENCES income_bands (code),

    -- religious practice and lifestyle
    religiosity              text CHECK (religiosity IN (
                                 'very_practising', 'practising', 'moderately_practising', 'not_practising')),
    prayer_frequency         text CHECK (prayer_frequency IN (
                                 'five_times', 'most_prayers', 'sometimes', 'jummah_only', 'rarely')),
    hijab                    text CHECK (hijab IN ('niqab', 'hijab', 'dupatta', 'occasionally', 'none')),
    beard                    text CHECK (beard IN ('full', 'trimmed', 'none')),
    religious_education      text CHECK (religious_education IN ('none', 'nazra', 'hafiz', 'alim')),
    smoking                  text CHECK (smoking IN ('no', 'occasionally', 'yes')),
    living_arrangement       text CHECK (living_arrangement IN ('with_family', 'separate', 'flexible')),
    work_after_marriage      text CHECK (work_after_marriage IN ('yes', 'no', 'flexible')),
    marriage_timeline        text CHECK (marriage_timeline IN (
                                 'within_6_months', 'within_1_year', 'within_2_years', 'not_decided')),
    jahez_stance             text CHECK (jahez_stance IN ('against', 'no_demand', 'family_custom')),

    -- free text (moderated, see 13-safety-and-moderation.md)
    about_me                 text CHECK (char_length(about_me) <= 1500),
    about_me_status          text NOT NULL DEFAULT 'approved'
                             CHECK (about_me_status IN ('approved', 'pending', 'rejected')),

    -- denormalised, maintained by the API
    completeness             smallint NOT NULL DEFAULT 0 CHECK (completeness BETWEEN 0 AND 100),
    has_approved_photo       boolean NOT NULL DEFAULT false,
    is_phone_verified        boolean NOT NULL DEFAULT false,
    is_photo_verified        boolean NOT NULL DEFAULT false,
    is_id_verified           boolean NOT NULL DEFAULT false,
    last_active_at           timestamptz,
    match_stale              boolean NOT NULL DEFAULT true,     -- recommendations must be recomputed
    match_refreshed_at       timestamptz,

    created_at               timestamptz NOT NULL DEFAULT now(),
    updated_at               timestamptz NOT NULL DEFAULT now(),

    CONSTRAINT profiles_required_when_submitted CHECK (
        status IN ('draft', 'deleted')
        OR (
            managed_by IS NOT NULL
            AND first_name IS NOT NULL AND last_name IS NOT NULL
            AND gender IS NOT NULL AND date_of_birth IS NOT NULL
            AND marital_status IS NOT NULL AND height_cm IS NOT NULL
            AND religion_code IS NOT NULL AND mother_tongue_code IS NOT NULL
            AND country_code IS NOT NULL
            AND (city_id IS NOT NULL OR city_other IS NOT NULL)
            AND education_level_code IS NOT NULL AND employment_type IS NOT NULL
        )
    ),
    CONSTRAINT profiles_hijab_only_female CHECK (hijab IS NULL OR gender = 'female'),
    CONSTRAINT profiles_beard_only_male CHECK (beard IS NULL OR gender = 'male'),
    CONSTRAINT profiles_married_only_male CHECK (marital_status <> 'married' OR gender = 'male'),
    CONSTRAINT profiles_wives_count_when_married CHECK (
        (marital_status = 'married') = (current_wives_count IS NOT NULL)
        OR marital_status IS NULL
    ),
    CONSTRAINT profiles_children_consistent CHECK (
        children_status IS NULL
        OR (children_status = 'none' AND COALESCE(children_count, 0) = 0)
        OR (children_status <> 'none' AND children_count >= 1)
    ),
    CONSTRAINT profiles_caste_choice CHECK (caste_code IS NULL OR caste_other IS NULL),
    CONSTRAINT profiles_sub_caste_choice CHECK (sub_caste_code IS NULL OR sub_caste_other IS NULL)
);

-- Discovery: opposite gender, active, most recently active first.
CREATE INDEX profiles_discovery_idx ON profiles (gender, last_active_at DESC) WHERE status = 'active';
CREATE INDEX profiles_dob_idx ON profiles (gender, date_of_birth) WHERE status = 'active';
CREATE INDEX profiles_city_idx ON profiles (city_id) WHERE status = 'active';
CREATE INDEX profiles_country_region_idx ON profiles (country_code, region_id) WHERE status = 'active';
CREATE INDEX profiles_caste_idx ON profiles (caste_code) WHERE status = 'active';
CREATE INDEX profiles_new_idx ON profiles (gender, first_activated_at DESC) WHERE status = 'active';
CREATE INDEX profiles_review_idx ON profiles (updated_at) WHERE status = 'pending_review';
CREATE INDEX profiles_text_review_idx ON profiles (updated_at) WHERE about_me_status = 'pending';
```

Column notes:

| Column | Note |
|---|---|
| `public_code` | Human-friendly id shown on the profile and used by support, for example `KR7F3K2QX9`. `KR` plus 8 characters of Crockford base32 (no I, L, O, U). Generated randomly at row creation; retry on a unique violation. |
| `date_of_birth` | The API rejects anyone younger than 18 on the day of submission. Other members only ever see the computed age. |
| `marital_status = 'married'` | Men only, for a man seeking another marriage. `current_wives_count` is then required and shown on the profile. Such profiles are shown only to women who explicitly accept it (see 10 section 3). |
| `caste_code` / `caste_other` | The caste is optional. The user either picks a row from `castes` or types a value into `caste_other`. Both NULL means "not stated". |
| `city_other` | Used only when the city is missing from `cities`. |
| `origin_city_id` | The family's place of origin ("belongs to"), which Pakistani families often ask about separately from the current city. |
| `completeness` | 0 to 100, recomputed by the API after every profile write (formula in 08 section 6). |
| `last_active_at` | Updated at most once every 5 minutes per profile by API middleware. |

```sql
CREATE TABLE profile_identity (
    profile_id         uuid PRIMARY KEY REFERENCES profiles (id) ON DELETE CASCADE,
    document_type      text NOT NULL CHECK (document_type IN ('cnic', 'nicop', 'poc', 'passport')),
    number_encrypted   bytea NOT NULL,                          -- 12-byte nonce || AES-256-GCM ciphertext || tag
    number_hash        bytea NOT NULL UNIQUE,                   -- HMAC-SHA256(pepper, namespace || ':' || normalised number), namespaces in 12 section 3
    number_last4       text NOT NULL CHECK (char_length(number_last4) = 4),
    status             text NOT NULL DEFAULT 'unverified'
                       CHECK (status IN ('unverified', 'pending', 'verified', 'rejected')),
    verified_at        timestamptz,
    created_at         timestamptz NOT NULL DEFAULT now(),
    updated_at         timestamptz NOT NULL DEFAULT now()
);
```

Rules:

- The plain number is never stored, logged, returned by any member API or sent to Sentry. The owner sees only `number_last4` (for example `*********1234`).
- `number_encrypted` uses the key in the `IDENTITY_ENCRYPTION_KEY` env variable (32 random bytes, base64). `number_hash` uses the separate `IDENTITY_HASH_PEPPER` env variable. Both are documented in [20-non-functional.md](20-non-functional.md) section 2.
- The unique index on `number_hash` enforces one profile per identity document. A second profile with the same number is rejected with the error `identity_already_registered`.
- The number of a banned user is copied into `banned_identities` (section 9.3) so that a banned person cannot register again.

### 5.6 partner_preferences

## 12. Deletion and retention

Accounts are scrubbed, not removed, so that other members' chat history and moderation records keep valid foreign keys.

When the purge job processes a user whose `purge_after` has passed (see 06 section 9), it runs these steps in one transaction and then deletes the R2 objects:

| Step | Action |
|---|---|
| 1 | Delete rows owned by the profile in: `profile_family`, `profile_contacts`, `profile_identity`, `profile_languages`, `profile_hobbies`, `partner_preferences`, `profile_privacy`, `profile_photos`, `photo_access` (both directions), `verification_requests`, `shortlists` (both directions), `passes` (both directions), `blocks` (both directions), `profile_views` (both directions), `saved_searches`, `match_recommendations` (both directions), `usage_counters`. |
| 2 | In `profiles`: set `status = 'deleted'` and set every column from `managed_by` down to `about_me` to NULL, except `gender`. Keep `id`, `user_id`, `public_code`, `gender` and the timestamps. |
| 3 | End every active connection of the profile with `ended_reason = 'account_closed'`. Set `deleted_at = now()` and `body = NULL` on every message the profile sent. The other member sees "Member no longer available" and "Message removed". |
| 4 | Mark pending interests in both directions as `expired`. |
| 5 | Delete `notifications`, `notification_preferences`, `user_devices`, `data_exports` for the user. Keep `user_consents`, `reports`, `sanctions` and `admin_audit_log`. |
| 6 | In `users`: set `status = 'deleted'`, `deleted_at = now()`, and set `email`, `phone_e164`, `status_reason` to NULL. Replace `clerk_user_id` with `'deleted:' || id` so the unique constraint still holds. |
| 7 | Delete the Clerk user through the Clerk Backend API, then delete every R2 object under the profile's prefixes. |

Retention periods:

| Data | Kept for |
|---|---|
| Account in `deletion_scheduled` | 30 days, then purged. Signing in during this time offers to cancel the deletion. |
| Messages of an ended connection | Until either member is purged, at most 12 months after the connection ended, then deleted by the cleanup job. |
| Verification images in R2 | 30 days after the decision (`media_purge_after`), then deleted. The decision itself is kept. |
| Temporary uploads never confirmed | 24 hours. |
| `profile_views` | 90 days. |
| `notifications` | 90 days. |
| `match_recommendations` | Replaced on each refresh; rows older than 14 days are deleted. |
| `usage_counters` | 30 days. |
| `jobs` in `succeeded` | 7 days. `dead` jobs: 30 days. |
| `webhook_events` | 30 days. |
| `reports`, `sanctions`, `admin_audit_log`, `banned_identities`, `user_consents` | 2 years after the account is purged. |
